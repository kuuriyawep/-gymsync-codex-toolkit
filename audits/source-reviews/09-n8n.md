## Findings

n8n is a full fair-code workflow automation platform, not a small Codex toolkit. Its license restricts distribution/provisioning in ways that make vendoring/copying unsuitable without legal review. Use architectural patterns as references, not copied implementation.

Useful patterns:
- Graph-based workflow execution and lifecycle contexts.
- Wait/suspend/resume, abort/cancel, partial graph execution, persistence.
- Lifecycle events before/after node/workflow, resume, response/chunk, and data fetch.
- Typed Zod/JSON tool schemas and action-discriminated tools.
- Capability-gated actions and deferred tool catalogs.
- Tool result/error guards, budgets, cancellation, checkpoints, subagent delegation, MCP.
- Stateful build → verify → repair → done/blocked lifecycle.
- Attempt/failure-signature tracking and duplicate setup claims.
- Deterministic safety classification plus an LLM classifier for ambiguous nodes; destructive/unknown/low-confidence actions fail safely.
- Separate publish action with explicit user approval.
- Evaluation harnesses for end-to-end builds, standalone agents, compatibility, tool events, pairwise judging, and context A/B tests.

Security/operations:
- Execute Command runs shell on the host.
- Custom/community nodes and webhooks require security review.
- Credential encryption and shared workflow credentials have least-privilege implications.
- Queue workers must share the correct encryption key.
- Some evaluation data setups can touch real Data Tables; side effects require scrutiny.
- Auto approval modes must not override this toolkit's explicit user approval requirements.

## Adoption decision

**ADAPT patterns only; do not copy or install the n8n runtime, nodes, or dependencies.**
