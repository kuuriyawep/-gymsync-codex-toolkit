# Documentation and Decisions
Document decisions when they affect architecture, data, security, dependencies, or future maintenance.
Record context, decision, alternatives, consequences, status, and date if known.
Update docs alongside behavior changes; do not document planned behavior as shipped.
Prefer targeted docs over duplicating the entire codebase. Link evidence and related changes.
