# Requirements Clarification
- Inspect available context and project behavior before asking questions.
- Separate user goals, constraints, assumptions, and non-goals.
- Ask one focused question at a time only when the answer changes the solution materially.
- Translate requirements into observable acceptance criteria and edge cases.
- Identify roles, permissions, data ownership, failure states, and migration needs where relevant.
- Do not invent requirements or broaden scope.
Deliver a short requirement brief and list unresolved decisions.
