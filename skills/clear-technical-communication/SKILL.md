# Clear Technical Communication

## When to use
Use when presenting technical findings, comparing engineering options, explaining system behavior, or reporting work that includes meaningful risk or uncertainty. This is a cross-cutting communication standard, not a replacement for the relevant technical workflow.

## Procedure
1. Lead with the answer, finding, or recommendation.
2. Separate verified facts, assumptions, hypotheses, and unknowns. Attach evidence to consequential claims.
3. Explain unfamiliar terms briefly while retaining standard technical terminology.
4. For bugs, distinguish symptom, confirmed/likely cause, proposed fix, and verification status.
5. For choices, compare only meaningful trade-offs, constraints, and failure modes; state the recommended option and why.
6. For execution reports, distinguish completed work from passed checks, and list failed, skipped, and unrun checks.
7. Match detail to the decision: concise for routine updates, explicit and structured for high-risk or irreversible work.

## Required output
Use only the sections needed, but make the following clear where applicable:
- Answer or recommendation.
- Evidence and confidence.
- Assumptions and unresolved questions.
- Risks and trade-offs.
- Next action or decision required.

## Boundaries
Do not overstate certainty, conceal caveats, fabricate evidence, or use verbosity to disguise an unsupported conclusion. Do not repeat background the reader already has unless it changes the decision.
